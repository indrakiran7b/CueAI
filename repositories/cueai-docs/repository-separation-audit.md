# CueAI Repository Separation Audit

**Audit date:** 2026-03-29  
**Workspace:** local CueAI monorepo (`cueai-android`)  
**Authoritative target:** 15 Bitbucket repositories from product screenshots  
**Method:** Directory inspection, sample file reads, import alias checks, config path checks. **No code was modified for this audit.**

---

## 1. Overall Result

## **DOES NOT MATCH**

**Why (evidence-based, not folder names alone):**

1. **Dual layout:** The runnable product still lives under **`apps/web`**, **`apps/api`**, and **`apps/desktop`**. Root `package.json` workspaces point only at `apps/*`, not at `repositories/cueai-*`.
2. **`repositories/` holds copies and partial slices**, not independent, buildable Bitbucket repos for most services.
3. **Microservice repos are incomplete:** Several contain 1–4 TypeScript files (or small Python slices) but **still import `@/lib/server/*` paths that exist only inside the full Next.js app**, so they cannot run alone.
4. **Duplication:** Full web, API, and desktop trees exist in both `apps/*` and `repositories/cueai-*`, plus overlapping modules (e.g. knowledge/RAG, live/screen, licensing) in **cueai-api**, **cueai-web**, and extracted service folders.
5. **cueai-gateway** and **cueai-infra** do not match Bitbucket descriptions (no gateway runtime; no Terraform/Kubernetes/Helm in tree).
6. **Unrelated project** `apps/journiq/` remains in the monorepo root and is not one of the 15 repos.

The separation is a **staging/mirror effort**, not a completed alignment with the 15-repository Bitbucket architecture.

## 11. Final Summary

**CORRECT:**

- All **15 Bitbucket repository names** have corresponding directories under `repositories/`.
- **cueai-desktop** mirror contains real Electron/overlay/hotkey/permission code for Windows and macOS.
- **cueai-web** mirror contains the real Next.js dashboard, admin UI, and user portal.
- **cueai-api** mirror contains a real FastAPI app with auth/workspace/license/entitlements modules.
- **cueai-docs** mirror contains substantive architecture and product documentation markdown.
- **cueai-knowledge-service** has the richest **partial** extraction (RAG TS + Python + tests/fixtures).

**NEEDS REVIEW:**

- **apps/journiq/** — different product; exclude from CueAI Bitbucket set.
- **macOS desktop** in cueai-desktop vs Bitbucket “Windows desktop” wording.
- **cueai-gateway** — placeholder vs future real gateway.
- **Where JSON store (`workspace-store.json`) lives** — web vs api boundary.
- **`extract-document.ts`**, **`poll-job.ts`** — shared vs resume vs knowledge ownership.

**WRONG LOCATION:**

- Microservice implementations still predominantly in **cueai-web** and **cueai-api** mirrors, not in exclusive service repos.
- **`fastapi-proxy.ts`** in cueai-gateway — not a gateway implementation.
- **`.venv`** under cueai-screen-context-service `tools/qwen-vl/`.
- **Dual canonical trees** (`apps/*` + `repositories/*`).

**MISSING:**

- Cloud **Terraform/K8s/Helm** in cueai-infra.
- Runnable **cueai-gateway**.
- Standalone **package/build config** for most microservice repos.
- **Cutover** from monolith paths to single canonical per Bitbucket repo.
